## French departments are now delivered as states of France

The 96 metropolitan departments and the 5 overseas departments and regions
(Guadeloupe, Martinique, Guyane, La Réunion, Mayotte) are now delivered in
standard as states attached to France (`country.isoalpha3 = 'FRA'`), the same
way states are already provided for the US, Italy, Japan, Indonesia, Mexico,
Argentina and Canada. This lets delivery carriers and tax rules discriminate
by department through the existing `country_area.state_id` / `tax_rule_country.state_id`
mechanism, with no core change required.

`isocode` carries the INSEE department code without country prefix (`01`,
`2A`, `971`, ...). Overseas collectivities that already exist as distinct
countries in this dataset (Saint-Pierre-et-Miquelon, Saint-Barthélemy,
Saint-Martin, Wallis-et-Futuna, French Polynesia, New Caledonia, French
Southern and Antarctic Lands) are not duplicated as states.

`country.has_states` stays at `0` for France: the department remains optional
on an address, exactly as before this update.

**If you already entered French departments by hand**: this migration only
adds a department when no `state` row already exists for France with the same
`isocode`. If you had created your own department states under a different
codification (a full ISO 3166-2 code such as `FR-75`, a region name, a custom
code, ...), those rows are left untouched and will coexist with the new
standard ones. Check your existing states under Configuration > Countries and
states and, if needed, migrate your `country_area`, `tax_rule_country`,
`address`, `cart_address` and `order_address` references to the standard
department rows before removing the duplicates yourself - this update does not
attempt that reconciliation and never deletes a `state` row.
